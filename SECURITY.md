# Security implementation and deployment

Updated 2026-10-06 (Step 9). These controls protect the current anonymous itinerary planner. It has no accounts, passwords, session cookies, uploads, or private saved itineraries. Account authentication, password hashing, ownership checks, database public keys, and row-level security become required when those features are introduced; SQLite is a server-only place cache today.

## Implemented controls

- Server keys stay in ignored environment files or platform secret storage. Browser code receives only a separate public Maps JavaScript key. Never place a server key in any `NEXT_PUBLIC_*` variable.
- Strict request schemas reject unknown fields, invalid coordinates, blank/oversized strings, dates outside supported bounds, and excessive visit durations. Requests are limited to 12 stops and 16 KiB; chunked requests are counted too. Body reading has a ten-second total deadline and compressed bodies are rejected.
- Per verified client IP (unchanged values): v1 endpoints 10/minute and 50/day each. v2 planning (`/api/v2/plan` and `/api/v2/plan/stream`) shares one 10/minute + 50/day allowance; v2 refresh and v2 comparison each have their own allowance with the same existing values. City/place suggestions and selections share one combined 30/minute + 100/day allowance (D36; counting selections in it is an interim choice pending a product decision). Forwarded IPs are trusted only when the connection peer is listed in `TRUSTED_PROXY_IPS`; the chain is read right to left and the first untrusted hop is the client (more than 16 entries or malformed values fall back to the peer). Whitelist exemptions cannot be spoofed using an untrusted forwarded header.
- Every actual outbound Google call (Autocomplete, Place Details, Text Search, Compute Routes) consumes a shared daily budget (2,000 by default) before it is sent, including unsuccessful or cancelled calls. Storage failures block calls (fail closed). Each admitted call is also recorded by kind in an accounting seam (`app/core/provider_accounting.py`) for later per-SKU controls; monthly free-tier enforcement is deferred and is not implemented. The budget limits anonymous automation and provider spending; it is not proof of a human user, a dollar cap or a free-tier guarantee. Provider console quotas are also required.
- Request admission (20/process), provider concurrency (20/process), provider queue deadlines, and solver concurrency (2/process) bound resource use. Solver work runs off the event loop with a time limit no longer than the remaining operation deadline; its slot is released when the worker thread ends. Planning, refresh and comparison share one 60-second deadline per operation that bounds every in-flight provider await; streamed operations stop on client disconnect and release capacity. Each open stream holds one admission slot for up to 60 s. Multiple replicas require capacity planning as these caps are per process.
- SQL uses parameters. The persistent Places cache (D38) stores only `place_id`, latitude, longitude and fetch time — no names, types, opening hours, addresses or search text. Rows expire one cleanup interval before 30 days after fetching (reads never extend expiry) and are deleted at startup and hourly. The legacy rich cache is migrated on first use (permitted fields only), dropped, and the file VACUUMed with secure_delete. Cache files use mode 0600 in a 0700 directory. This cannot erase copies in earlier backups or volume snapshots; remove those according to retention policy. Rich place details are fetched per operation and kept in memory only.
- React renders user content as text. Browser scripts use a fresh CSP nonce per response; production script policy has no unsafe-inline or unsafe-eval. Inline styles remain enabled for Google Maps. Security headers prevent framing and MIME sniffing, restrict referrers, and disable response caching. API docs and schema endpoints are disabled; developers may generate the schema offline with `app.openapi()`.
- API validation responses omit submitted values and unknown field names. Unexpected failures return a generic 503 (`service_unavailable`), or a generic `internal_error` stream event, with no exception text. Provider bodies/exception text and request payloads are excluded from application logs. Health checks omit environment details.
- Logging (Step 9, D46): one JSON line per v2 operation on stdout (`routewright.metrics`): operation, transport, bounded outcome/failure categories, elapsed time, stop count and provider-call counts by kind. It never contains place names/IDs, coordinates, travel dates, IPs, operation IDs, plans, payloads, secrets or provider text; comparison savings are not logged and completed comparisons are one category until permitted use is confirmed. Uvicorn runs with `--no-access-log`, so the application does not print client IPs. Retention is the hosting platform's log retention; Railway documents 7 days (Hobby), 30 days (Pro), up to 90 days (Enterprise) — the project's actual plan must be confirmed. Railway's own HTTP logs record client IPs (`@srcIp`); this is outside the application's control and must be covered by the privacy policy and access controls.
- Dependencies are updated and locked. Python installs verify package hashes. CI blocks Python vulnerability findings, runtime npm vulnerabilities, and new high/critical frontend development findings. Weekly CI repeats scans. Secret scanning covers full Git history and source files, with findings redacted.

## Required production configuration

1. Provision a private Redis instance; set `RATE_LIMIT_STORAGE_URI` on every backend replica to the same database. Use `rediss://` for remote connections and restrict network access. The backend refuses production startup with memory storage or an unavailable store. Do not evict/flush rate-limit keys during normal operations. Redis connect/read operations have two-second timeouts; add infrastructure health alerts.
2. Set `APP_ENV=production`, `GOOGLE_MAPS_API_KEY`, and `ALLOWED_ORIGINS=https://your-frontend-domain`. Configure only the real HTTPS frontend origins. CORS does not authenticate callers: this API is intentionally public.
3. Configure `TRUSTED_PROXY_IPS` with the actual ingress connection peers/CIDRs. The ingress must replace or safely append `X-Forwarded-For`; block direct access bypassing it. Uvicorn runs with `--no-proxy-headers` so the application sees the actual peer. Leave trust empty until the provider's topology is verified. `TRUSTED_PROXY_COUNT` is obsolete and rejected.
4. Set frontend `NEXT_PUBLIC_API_URL=https://your-backend-domain`. Enforce HTTP-to-HTTPS redirects at the ingress for both domains. After verification enable backend `HSTS_ENABLED=true` and frontend `SECURITY_HSTS_ENABLED=true`. TLS termination belongs to the ingress; the application cannot prove it is enabled from local code.
5. Create separate Google keys. Restrict the browser key by website referrer and Maps JavaScript API; restrict the server key to Places API (New) and Routes API, and server egress IP where supported. Set Google quotas, billing alerts, and a provider budget appropriate to your traffic. Never share keys in chat. Rotate any previously exposed key before rewriting Git history; history cleanup requires coordination with collaborators.
6. Store SQLite on a private encrypted volume; restrict backups and retention. Start the backend with a restrictive umask (Docker does this). Monitor generic failure/capacity metrics without recording locations or submitted queries.

Local checks cannot verify these platform settings or live key restrictions. The browser smoke test uses no Maps key, so live Google Maps loading under CSP remains a deployment check. Docker build and live Redis integration must pass in the deployment environment before release.

## Verification commands

From `backend`: install `requirements-dev.lock` with `pip install --require-hashes -r requirements-dev.lock`, then run `python -m ruff check .`, `python -m ruff format --check .`, `python -m mypy app`, and `python -m pytest -q`.

Shared-store tests: set `SECURITY_TEST_REDIS_URL` to a disposable Redis database (they flush it), e.g. `redis://127.0.0.1:6390/15` on a throwaway `redis:7.4-alpine` container; CI provides one.

From `frontend` on Node 22.13+ (22.x) or Node 24+: run `npm ci`, `npm run type-check`, `npm run lint`, `npm run test:unit`, `npm run check:types-drift`, `npm run security:audit`, then build with a fake server key present — `GOOGLE_MAPS_API_KEY=<probe> NEXT_PUBLIC_API_URL=https://api.routewright.invalid npm run build` — and run `SECURITY_BUNDLE_PROBE=<probe> npm run security:bundle` (fails if the server key or key-shaped strings are bundled). Install Playwright Chromium, then run `npm run security:smoke` and `npm run test:e2e` (mocked API; no Google quota).
